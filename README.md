# BEAST 先輩

`MV_完成版.mp4`（INMU KING / 4分07秒 / 133 BPM）専用の音ゲー。
MVそのものがプレイフィールドで、MVのカット割りが譜面になっている。

## 遊ぶ

`start.bat` をダブルクリック。ブラウザが開く（http://localhost:8730/）。
閉じるときは開いた黒いウィンドウを閉じる。

> ファイルを直接ダブルクリックしても動かない。ES モジュールと音声デコードに
> HTTP が要るのと、MVのシークに Range リクエストが要るため。

### 2つのモード

選曲画面の上のセグメントを **Q / E**（クリックでも可）で切り替える。
選曲画面は上にモード、中央に曲、左に自己ベスト、右に譜面の中身（密度グラフつき）。

**4レーン** — MVの上に浮かぶ奥行きのあるハイウェイに落ちてくるノーツを叩く。

| | |
|---|---|
| **D F J K** | 4レーン（SETTINGS で変更可） |
| **Space** | CUT ノーツ専用 |

- **タップ**（水色／白）… 判定ラインに重なった瞬間に叩く
- **ロング**（緑）… 光が終わるまで押しっぱなし。早く離すとミス
- **CUT**（黄・横一列）… MVの画が切り替わる瞬間。どのキーでもOK

**たいこ** — 一本レーンを右から左へ音符が流れる。**ドンとカを区別する。**

| | |
|---|---|
| **F J**（内側） | ドン |
| **D K**（外側） | カ |
| **Space** | ドン |

打撃音は円形膜の固有モード（1.000 / 1.594 / 2.136 …）を重ねた合成音です。
ドンは約100Hzで280ms、カは約425Hzで80msに落ちます。毎回わずかに音程を散らして
連打が機械的に聞こえないようにしてあります。

- **ドン**（マゼンタの塗り）… 低域＝キックと表拍
- **カ**（シアンの輪）… 高域＝ハイハットと裏拍
- 違う側で叩くと **不可**。音符は消えます（太鼓と同じ）
- **大音符**（ひとまわり大きい）… 同じ側の2キーを同時で「大」成立、2倍の価値。1つでも取れる
- **連打**（黄色い長い棒）… 棒の間ずっと叩く。どちらの側でもよく、回数ぶん入る
- 判定は **良 / 可 / 不可** の3段階（良 ±34ms、可 ±80ms）

ドンとカは音から決めています。キック（低域）は必ずドン、グリッド外の細かい音はカ、
それ以外は表拍＝ドン・裏拍＝カ、16分は交互。同じ側が5つ続いたら折り返します。
おにで ドン722 / カ538 とだいたい 57:43 になります。

どちらのモードも **Esc** でポーズ、スマホは画面を叩く（たいこは画面を4分割して多重タップ＝大音符）。

### HYPE

繋ぐほど上がり、ミスで冷める。HYPE が高いほど MV の彩度・ブルーム・判定ラインの
発光が強くなる。スコアとは独立していて、**MVを一番アツい状態で流しきる**のが裏の目的。

### 難易度（フルバージョン）

| | Lv | 4レーン | たいこ |
|---|---|---|---|
| ふつう | 5 | 581 | 436 |
| むずかしい | 8 | 987 | 790 |
| おに | 12 | 1536 | 1286 |
| **裏** | **20** | **2532** | **1999** |

裏は、拾える音を全部拾ったうえで、盛り上がっている所を16分で埋め、
いちばん激しい所に32分を差し込んでいます。平均 11.5 ノーツ/秒、瞬間 18 ノーツ/秒。
同じレーンの連打は最短 113ms まで（物理的には通る）に抑えてあります。

### スコア

**全良フルコンボでちょうど 114514。**

| | |
|---|---|
| ノーツ素点 | 満点から下のボーナスを引いた残りを、1ノーツずつ均等に配る（端数は頭から1点ずつ） |
| 大 / CUT | 1個 **+45** |
| 全キメ | 大 / CUT を全部取ると **+810** |
| 全良 | 判定が全部いちばん上で **+514** |
| フルコンボ | コンボを切らずに完走で **+1145** |

判定の重みも 1.000 / 0.810 / 0.514 / 0.114。4モード×4難易度すべてで満点が
ちょうど 114514 になることを確認済みです。

### 判定とスコア

4レーン： JUST ±28ms / COOL ±55ms / GOOD ±90ms / BAD ±125ms / それ以降 MISS
たいこ： 良 ±34ms / 可 ±80ms / それ以降 不可

スコアはどちらも 精度 90万点 + コンボ 10万点の満点 100万点。
たいこの大音符は2キーで取ると2ユニットぶんの価値になります。
記録は モード × バージョン × 難易度 ごとに保存されます。

初回は **CALIBRATE** を一度やると気持ちよさが変わる。
リザルト画面の「この値にする」でも自動調整できる。

## スマホ

- 画面下に**叩きパッド**が出ます。
  - **たいこ** … 黒ぶちの付いた肌色の半円。**半円の中＝ドン（左右で手を分ける）、
    半円の外は画面のいちばん上までぜんぶカ**（左右で手を分ける）。
    文字は置かず、カの面には色も乗せません（完全に透明）。どこを叩いても無駄になりません。
  - **4レーン** … 画面を縦に4分割。**左から順にレーン1〜4**です。
  - **叩きパッドは画面に描きません**（枠も文字も出しません）。MVを一切隠さないためです。
    判定線やレーンの光りかたで叩く位置はわかります。
  - 画面下にパッドの高さぶんの余白を確保して判定線を上げるので、親指でノーツが隠れません。
  - 判定文字がHUDとぶつからない高さまで、たいこのレーンを自動で下げます。
- 狭い画面では音符を小さくし、スクロールも詰めて重ならないようにしています。
  それでも**よこ画面のほうが圧倒的に見やすい**ので、縦のときは案内を出します。
- 画面右上に**全画面ボタンを常時表示**。プレイ開始でも自動で全画面に入ります（横向き固定も試みます）。
- プレイ中はその左に**一時停止ボタン**が出ます（キーボードなしでも止められます）。
- iPhone の Safari は全画面APIに対応していないので、**共有 → ホーム画面に追加**すると
  フルスクリーンで起動します（`manifest.webmanifest` で `display: fullscreen` 指定済み）。
- ノッチのある端末向けに `env(safe-area-inset-*)` を効かせてあります。
- 横向きで画面の高さが足りない端末（CSS で 560px 以下）では、タイトルを左右2段組みにし、
  選曲カード・設定・リザルトを詰めて**画面内に収まる**ようにしています。
- 幅の狭い端末（CSS で 620px 以下）では、プレイ中のHUDを2段にして
  HYPEゲージを下の段いっぱいに広げます（スコアと難易度が潰れません）。

## 打撃音

**叩いたら必ず鳴ります。**ノーツに当たっていなくても、太鼓と同じで音は出ます。
4レーンでも同じです。判定を待たず、押した瞬間に鳴らしているので遅れません。

小さいと感じたら SETTINGS の **打撃音の音量**（0〜250%、既定110%）で上げてください。

### 映像の置きかた（重要）

**GitHub Pages は Git LFS のファイルを配信しません。** LFS に入れると、動画の代わりに
134バイトのポインタのテキストが返ってきて MV が再生できません（一度これで踏みました）。

そのため：

| | |
|---|---|
| `assets/mv_720.mp4` | **41.9MB・通常ファイル**。これを配信する |
| `assets/mv_1080.mp4` | ローカル専用。`.gitignore` 済みでコミットしない |

読み込み側は 1080p → 720p の順に試すので、1080p が無い公開版でも自動で 720p になります。

GitHub の制限は 1ファイル 100MB（50MB で警告）。720p は 2パス 1350kbps で約42MB に
収めてあります。作り直すときは：

```bat
node toolsuild.mjs
```

> 以前 LFS に入れた 355MB のオブジェクトは履歴に残ったままで、LFS の容量を使い続けます。
> 完全に消すには履歴の書き換えが必要です（やらなくても公開サイトは動きます）。

### 見た目の決めごと

- 角は丸めず **45度に落とす**（`.bev` / `.cut`）。均一な角丸はチープに見えるので使わない。
- 書体は同梱。日本語 **Zen Kaku Gothic New**（500/700）、数字と英字 **Chakra Petch**（600/700）。
  CDN は参照していないので、ネットがなくても同じ見た目になる。入れ直すときは
  `node toolsetch-fonts.mjs`。
- 線は 1px、余白は 4px 刻み、数字は等幅字形。強調は色面ではなく**細い罫とアクセントの縦線**で作る。

### 時計の作り

- 曲は丸ごと `AudioBuffer` に展開し、`AudioContext.currentTime` を唯一の時計にする。
  `outputLatency` を引いて「いま耳に届いている位置」を出す。
- キー入力は `event.timeStamp` からオーディオ時計へ変換して判定する（フレーム単位より細かい）。
- MV は音に追従させる。ずれが 45ms を超えたら再生速度で吸収し、
  300ms を超えたらシークし直す。実測ドリフトは ±15ms 程度。
- 再エンコードした AAC がブラウザで元波形と 1ms 以内で一致することは実測確認済み
  （先頭パディングによる系統ズレなし）。

## 譜面の作りかた

自動生成。手順は全部 `tools/` に入っている。

1. **analyze.mjs** — STFT（窓1024 / ホップ256 = 5.8ms）でスペクトルフラックスを取り、
   低域(30-220Hz) / 中域(220-2.2k) / 高域(2.2k-14k)に分けて onset を検出。
   自己相関で BPM、コムフィルタで拍の位相も出す。
2. **onset-bias.mjs** — 検出時刻と実際の波形の立ち上がりのズレを実測（この曲は +6.9ms）。
3. **tempo-refine.mjs** — onset 群への位相ロックで BPM を小数まで追い込む。
   この曲は **133.000 BPM**（ロック強度 0.4477 / 次点 0.059 と差が明確）。
4. **generate-charts.mjs** — 16分グリッドへスナップして譜面化。
   - 強い onset は 16分グリッドに ±15ms で 80% 一致する。
     逆に**グリッドから外れた弱い音は環境音や声の揺れ**なので捨てる。
   - 低域は外側レーン、中高域は内側に寄せ、直前のレーンとの連打を避け、
     左右の使用量が偏らないように配る。16分の連なりは階段にする。
   - 中域が伸びている区間はロングノーツ、MVのカットと一致する音は CUT ノーツ。

### 別のMVで作り直す

```bat
node tools\build.mjs "C:\path\to\別のMV.mp4"
```

WAV抽出 → カット検出 → 音声/映像エンコード → 解析 → 譜面生成 まで通しで走る
（映像の再エンコードに数分）。曲名は `tools/generate-charts.mjs` 末尾の `manifest` を
書き換えて `node tools/generate-charts.mjs` で反映。

ffmpeg は PATH か、`C:\Program Files\KeepStreams\KeepBeats\` などから自動で探す。

## 調整メモ

- 重いときは SETTINGS の **映像の画質 → 720p**、**エフェクト強度を下げる**。
  映像 OFF でも音ゲーとしては成立する。
- ノーツが見づらいときは **映像の暗さ** を上げる。
- **奥行き** を 0% にすると普通の縦スクロール音ゲーになる。
- ブラウザのコンソールから `BEAST.game` `BEAST.audio` などを触れる（`MVBEAT` でも同じ）。
